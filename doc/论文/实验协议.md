# 面向资源受限 RTOS FPGA SoC 的三级 3D 卸载实验协议

## 1. 目的与研究问题

本协议用于回答：在同一 RTOS FPGA SoC、同一低模工作负载和同一输出后端下，将 3D 几何处理从 CPU 逐步卸载到矩阵乘法器、再卸载到整帧 Scene Controller，能否释放更多 CPU 可调度时间，同时维持实时帧预算，并以可接受的 FPGA 资源代价实现。

本协议在正式实验开始前冻结。正式数据产生后不得改变主指标、成功门槛、样本数、异常处理或统计口径；如发现测量链路错误，只能记录为协议偏差、修复后重新冻结并重新开始一组完整实验。

## 2. 比较方案

三种方案必须使用同一模型解析器、资产版本、定点格式、三角函数 LUT、投影、背面剔除、Painter 稳定排序、三角形命令编码、SketchBook 后端、RGB332 输出、动画轨迹和 RT-Thread 后台任务。差异仅限于几何计算的执行位置和等待方式。

| 方案 ID | 名称 | CPU 工作 | 硬件工作 | 等待方式 |
|---|---|---|---|---|
| `CPU_ONLY` | CPU 全几何 | Transform、Triangle/构面、背面剔除、Painter Sort、Command Submit 全部由 CPU 完成 | SketchBook 栅格化/帧缓冲 | 不调用几何加速器 |
| `CPU_MATMUL` | CPU + 矩阵乘法器 | CPU 完成构面、剔除、Painter Sort、Command Submit；顶点 Transform 通过 MMIO 矩阵乘法器完成 | 矩阵乘法器执行 Transform；SketchBook 栅格化/帧缓冲 | CPU 计时包含 MMIO 装载、启动、轮询/完成读取全部开销 |
| `SCENE_CONTROLLER` | 整帧 Scene Controller | CPU 更新场景参数、提交 `CLEAR + DRAW* + PRESENT` 帧命令、处理/等待完成；不执行逐顶点/逐三角形几何 | Scene Controller 完成模型读取、Transform、构面、剔除、Painter Sort 和命令生成；SketchBook 栅格化/帧缓冲 | 正式主结果使用阻塞等待/完成事件；保留轮询对照字段，不得把轮询时间从端到端延迟中删除 |

`CPU_MATMUL` 是主比较基准。`CPU_ONLY` 用于量化矩阵乘法器的增益，`SCENE_CONTROLLER` 相对 `CPU_MATMUL` 的差值用于检验整帧卸载假设。若最终实现尚未具备 Scene DONE 中断，必须将其标记为协议偏差，不能把轮询版结果冒充阻塞版结果。

## 3. 固定平台、时钟与实现条件

- CPU 周期计数以 `rdcntvl.w` 或等价单调硬件计数器读取，CPU 频率固定记录为 33 MHz；`cpu_cycles / 33,000,000` 转换为秒。
- 外设/RTL 时钟固定记录为 50 MHz；RTL 周期只用于 Scene/SketchBook/AXI 内部计数，不能与 CPU cycles 直接相加，除非通过明确的时钟域换算并另列字段。
- 所有方案使用相同编译器、优化选项、链接脚本、RT-Thread 配置、缓存配置、内存镜像、资产加载地址和硬件时钟配置。
- 计时区间内禁止 UART 打印、人工输入、动态内存分配和调试断点；诊断输出写入缓冲区，在计时区间外批量输出。
- 每个条件先预热 30 帧；预热帧不进入正式统计。预热期间完成模型加载、缓存填充和首次初始化，或明确记录其未完成状态。
- 正式每个条件运行 300 帧，独立重复 5 次。每次重复重新上电/复位或采用相同的可验证复位流程，并重新加载同一镜像；重复编号为 `rep=1..5`，帧编号为 `frame=1..300`。
- 仿真应运行完整模型族×三级方案；上板正式点为轻载、中载拐点、满载。中载点必须在冻结清单中预先给出，不能看完结果后挑选。
- 不得修改 `FRAME_DUMP_LIMIT(0)`。帧图像转储是否开启必须作为配置项记录，不能只保留人工挑选的帧。

## 4. 工作负载与等价性

### 4.1 模型族

正式模型规模点为 `(V,T,M)`：

| 点 | 顶点 V | 三角形 T | Mesh M |
|---|---:|---:|---:|
| S0 | 16 | 24 | 1 |
| S1 | 32 | 48 | 2 |
| S2 | 64 | 96 | 4 |
| S3 | 96 | 144 | 8 |
| S4 | 128 | 192 | 16 |

其中 V/T/M 分别为模型顶点数、三角形数和 mesh 数；单模型容量不得超过硬件约束。每个规模点使用确定性资产、固定 SHA-256、固定模型包目录和固定生成器版本。除规模扫描外，至少建立 V-only、T-only、M-only 单因素控制组：改变一个因素时固定另外两个因素，便于区分几何、排序和多 mesh 调度开销。

统一使用正交投影、4 bit 相位 LUT、Q8.8 缩放、既定定点乘法右移规则、固定视口、RGB332 平面着色和 Painter's Algorithm；不纳入纹理、Z-buffer、透视投影或动态光照。动画轨迹固定为 16 帧循环；每个重复从轨迹帧 0 开始，连续运行 300 帧。

### 4.2 输出等价性

等价性是性能结论的前置条件。对同一 `(asset_hash, V,T,M, trajectory_frame)`，逐帧比较：

1. 三角形命令序列的长度、顺序、命令类型、顶点坐标、颜色、裁剪结果和 mesh 标识；排序相同深度时必须使用同一稳定 tie-break 规则。
2. 后页 framebuffer 的完整 CRC；必要时保存首个差异命令索引、字段和首个差异像素坐标/值。
3. `PRESENT` 后完成帧的帧号及错误状态。

命令序列或 framebuffer CRC 任一不一致，该帧标记 `equivalence=FAIL`，其性能数值不得进入主判据汇总；不得以“视觉上相同”、跳过差异帧或只比较抽样像素替代完整比较。若差异来自已书面批准的后端量化差异，必须在正式冻结前定义容许规则和独立字段；冻结后不得临时放宽。

## 5. 指标与严格定义

### 5.1 主指标：CPU active cycles/frame

`active_cycles` 是 CPU 在一帧场景事务中实际执行该方案规定的软件工作所消耗的 CPU 周期数。计时从本帧第一条场景处理相关软件指令前的计数器采样开始，到最后一条场景提交/完成处理软件指令后的计数器采样结束；包含函数调用、MMIO、队列操作和必要的完成处理，不包含 UART 输出、帧外调度和预热。

- `CPU_ONLY`：包括 Transform、Triangle/构面、Cull、Painter Sort、Command Submit。
- `CPU_MATMUL`：包括矩阵装载/启动、轮询或完成读取、顶点结果整理，以及 CPU 构面、Cull、Sort、Submit。
- `SCENE_CONTROLLER`：包括参数写入、命令提交、完成事件处理；CPU 等待期间不计入 `active_cycles`，但必须单独记录阻塞时间。

主效应以每个条件的 5 次重复合并后的帧级 `active_cycles` 中位数计算。相对 `CPU_MATMUL` 的下降率为：

`active_reduction = 1 - median(active_cycles_SCENE) / median(active_cycles_MATMUL)`。

主判据为 `active_reduction >= 0.30`，即至少下降 30%。同时报告均值、标准差、中位数、P95、P99、最大值和 95% 置信区间；均值不能替代预先规定的中位数主判据。

### 5.2 帧延迟、实时预算与 P99

`frame_latency` 是同一帧从“帧处理开始”到该帧 `PRESENT` 在显示管线完成并可被完成帧计数确认的墙钟时间；不得用 CPU active 时间代替。起点和终点必须在三种方案中使用同一语义，并记录对应的硬件/CPU 时间戳。对于 vblank 同步的双缓冲，终点以完成帧副本/完成事件为准，不能以写入 `PRESENT` 寄存器的时刻冒充显示完成。

30 FPS 预算为 `1/30 s = 33.333... ms`，报告时写为 `33.333 ms`，判定使用未四舍五入的纳秒或周期值：`frame_latency <= 33,333,333 ns`。P99 使用 1500 个正式帧（5×300）按最近秩法计算；若某条件有效帧不足 1500，标记 `P99=INVALID`，不得用插值补齐。

相对 `CPU_MATMUL` 的 P99 增幅为：

`p99_increase = p99_latency_SCENE / p99_latency_MATMUL - 1`。

约束判据同时满足：`p99_increase <= 0.10`（增幅不超过 10%）且 `p99_latency_SCENE <= 33.333 ms`。任何正式帧超预算都保留计数、最大值和超预算比例；“P99 未超预算”不掩盖个别超时帧。

### 5.3 分解与支持指标

每帧至少记录以下字段：

- `transform_cycles`、`triangle_cull_cycles`、`painter_sort_cycles`、`command_submit_cycles`；不适用阶段填 0，并以 `na_reason` 说明。
- `active_cycles`、`polling_cycles`、`blocked_cycles`、`wall_cycles`/`frame_latency_ns`。
- `V`、`T`、`M`、输入三角形数、剔除三角形数、输出三角形数、Scene/AXI 读取字节数和事务数。
- `frame_crc`、命令序列 CRC、错误位、超时位、等价性状态、首个差异位置。
- RT-Thread `idle_cycles`、`idle_rate`、固定低优先级后台任务完成量；后台任务算法、优先级、周期、输入和计时窗三种方案一致。

`polling_cycles` 只表示 CPU 在主动读取状态寄存器上的周期；`blocked_cycles` 表示等待 Scene 完成事件/信号量而未运行的墙钟时间。二者不得从 `frame_latency` 中扣除。`wall_cycles` 仅在单一可校准计时域内使用；跨时钟域结果优先保存纳秒。

## 6. 统计与报告规则

原始数据以一帧一行 JSONL 或等价 CSV 保存，另附运行级元数据。每行必须包含协议版本、代码版本、方案、重复/帧编号、资产哈希、配置哈希、V/T/M、全部周期字段、延迟、CRC 和状态。统计脚本只读取通过 schema 校验且 `equivalence=PASS`、`error=NONE`、`timeout=false` 的帧计算主判据；排除数量按条件报告，不能静默删除。

每个条件报告 mean、median、P95、P99、max、样本数、剔除数、效应量和 95% CI，并分别给出仿真与上板结果。正式决策先按每个规模点判断，再给出跨规模汇总；跨规模汇总不得用不同规模的原始帧简单混合掩盖某一规模失败。资源代价另行记录 LUT、FF、BRAM、DSP、WNS/Fmax，功耗不作为主判据。

## 7. 失败、超时与协议偏差

- 编译失败、TB `$fatal`、RTL/软件错误位、模型 CRC 错误、命令溢出、丢失完成事件或仿真缺少必要顶层，均为该条件 `RUN_INVALID`，保留日志和结构化错误，不能记作性能 0。
- 任何帧超时都标记 `timeout=true`；该重复的性能汇总无效，但其他重复仍须保留。若 5 次重复中有一重复无法完成，条件判定为 `INCOMPLETE`，除非重新按完整协议执行该重复。
- Verilator 适用于确定性 RTL/握手性能；涉及 X/Z、三态、Xilinx IP、MIG DDR3、CDC 或 Verilator 与 RTL 协议语义冲突时，补用 ModelSim，并在报告中标明模拟器和原因。
- 修改代码、资产、编译参数、计时点、驱动等待方式、工作负载或分析脚本后，必须递增协议/配置哈希并重新执行冻结；不得将不同配置拼成一个重复集。

## 8. 冻结清单与成功判定

正式实验开始前冻结并归档：Git commit、分支、工作树状态、协议版本、工具链版本、RTL/软件配置宏、CPU/RTL 时钟、资产清单及 SHA-256、模型生成器版本、轨迹、仿真 TB/filelist、板卡 bitstream、结果 schema/统计脚本和本协议文件哈希。先导实验只能验证测量链路，不得进入正式结果或用于调整门槛。

在等价性通过且数据完整的条件下，`SCENE_CONTROLLER` 相对 `CPU_MATMUL` 只有同时满足以下三项，才报告“支持研究假设”：

1. `active_cycles` 中位数下降至少 30%；
2. 帧延迟 P99 增幅不超过 10%；
3. 帧延迟 P99 不超过 33.333 ms。

任一项失败都如实报告为未满足，不通过优化后临时改判据。若满足性能判据但 FPGA 资源/Fmax 不满足设计约束，则报告为“性能通过、实现代价受限”，不得合并为总体成功。所有原始帧、失败帧、日志、波形索引、PPM 活动记录和统计输出均保留，以保证结果可复核。
