# 整改行动

> 创建于 2026-08-30，主题：科研、论文

用我们的git进行任务进度管理

### 第一阶段：冻结基线与实验协议

- **T01：编写实验协议**
    
    - 固定三级方案、指标定义、30 FPS预算、30%/10%判据、模型规模和重复次数。
    - 产物：`doc/论文/实验协议.md`。
    - 验收：后续不得根据结果临时改变主判据。
- **T02：冻结当前基线**
    
    - 记录Git版本、配置宏、软件镜像、资产版本、现有仿真结果、Vivado资源及时序。
    - 验收：能够重新生成“修改前”结果。
- **T03：建立统一结果格式**
    
    - 定义每帧输出字段：方案、V/T/M、active/polling/wall cycles、各阶段cycles、frame latency、CRC、错误状态。
    - 建议输出UART CSV或JSON行，便于脚本自动汇总。

### 第二阶段：独立测试软件

- **T04：创建 `rt_3d` benchmark**  可参考
    
    - 新建 `sdk/software/examples/rt_3d/`，不修改原有 `sk_os`业务逻辑,保持Rt thread功能
    - 支持固定帧数、固定轨迹、固定模型和无人工交互运行。
- **T05：建立统一模式接口**
    
    - 编译时选择：
        1. `CPU_ONLY`
        2. `CPU_MATMUL`
        3. `SCENE_CONTROLLER`
    - 三者共用模型解析、定点格式、LUT、剔除、排序和SketchBook后端。
- **T06：增加CPU分阶段计时**
    
    - 分别统计Transform、Triangle/Cull、Painter Sort、Command Submit和Polling。
    - 复用现有`rdcntvl.w`周期计数能力。
- **T07：增加RTOS系统指标**
    
    - 统计idle cycles/idle rate。
    - 增加固定低优先级后台任务，记录单位时间完成量。
    - 保证后台任务算法和优先级在所有方案中一致。

### 第三阶段：必要RTL升级

- **T08：Scene Command FIFO扩至32项**
    
    - 将深度参数化，补满/空/锁定/溢出测试。
    - 验证`CLEAR + 16 DRAW + PRESENT`完整提交。
    - 比较扩容前后的LUT、FF、BRAM和Fmax。
- **T09：实现Scene DONE中断**
    
    - 增加IRQ enable/status/clear。
    - 覆盖render done、frame done和error；明确使用电平还是脉冲中断。
    - 验收：不轮询也不会丢失完成事件。
- **T10：接入SoC与RT-Thread阻塞等待**
    
    - 将Scene IRQ接入中断控制器。
    - BSP提供轮询和中断两种等待API。
    - `rt_3d`使用信号量或事件阻塞，保留轮询模式用于对照。
- **T11：增加Scene性能计数器**
    
    - 统计LOAD字节/读事务、Transform cycles、Triangle/Cull cycles、Sort cycles、Command cycles、输入/剔除/输出三角形数。
    - 计数器只观测，不改变流水行为。

### 第四阶段：三级基线实现

- **T12：完成CPU-only几何链**
    
    - CPU完成变换、构面、背面剔除、Painter排序。
    - 输出与Scene Controller相同的SketchBook三角形命令。
- **T13：完成CPU＋矩阵乘法器方案**
    
    - 复用现有 [matmul.c (line 1)](/D:/FPGA/ciciec2026_loongson_preliminary/sdk/software/bsp/drivers/matmul.c:1)。
    - 仅卸载顶点变换；CPU继续构面、剔除和Painter。
    - MMIO装载、等待和结果读取时间全部计入，不能隐藏调用开销。
- **T14：完成Scene Controller方案**
    
    - CPU仅更新动画/场景参数、提交帧命令并阻塞等待。
    - 分开记录CPU active、阻塞时间和端到端延迟。

### 第五阶段：正确性与工作负载

- **T15：建立输出等价性测试**
    
    - 比较三角形命令序列、稳定排序、framebuffer CRC。
    - 不一致时输出首个差异命令/像素，而非只给PASS/FAIL。
- **T16：生成参数化模型族**
    
    - 基础点：`(16,24,1)`、`(32,48,2)`、`(64,96,4)`、`(96,144,8)`、`(128,192,16)`。
    - 另做单独改变V、T、M的控制组。
    - 模型应有确定性资产生成脚本和清单。
- **T17：建立专用benchmark testbench**
    
    - 自动等待UART检查点、抓取命令、计算CRC、记录精确硬件周期。
    - 结果写入结构化JSON，不依赖人工读transcript。

### 第六阶段：先导、冻结与正式实验

- **T18：运行先导实验**
    
    - 只验证测量链路、超时范围和统计脚本。
    - 使用不进入正式结果的模型。
    - 发现问题可以修测量系统，但不能据此调整成功门槛。
- **T19：冻结正式实验清单**
    
    - 固定代码版本、模型哈希、配置、脚本、规模点和统计方法。
    - 中载上板点按仿真曲线的预设拐点规则选择。
- **T20：运行完整RTL仿真**
    
    - 全模型族×三级方案。
    - 收集等价性、阶段周期、增长趋势、剔除率和外存访问。
- **T21：运行上板实验**
    
    - 轻载、中载、满载。
    - 每组预热30帧，正式300帧×5次。
    - 若要强调P99，建议每条件累计至少1000个正式帧。
- **T22：重新综合所有硬件配置**
    
    - 至少比较原始FIFO、FIFO32＋中断、最终Scene版本。
    - 记录LUT、FF、BRAM、DSP、WNS/Fmax；功耗不作为主指标。

### 第七阶段：数据分析与论文决策

- **T23：建立自动统计脚本**
    
    - 输出均值、中位数、P95、P99、最大值、效应量、置信区间。
    - 同时生成CPU cycles—P99延迟—资源代价图。
- **T24：执行主判据**
    
    - 与CPU＋矩阵乘法器相比：
        - active cycles下降是否≥30%；
        - P99增幅是否≤10%；
        - 是否满足33.3 ms预算。
    - 无论通过与否都保留完整结果。
- **T25：数据出来后再决定额外优化**
    
    - 只有瓶颈证据明确时，才考虑流水化Scene、扩大Cache、优化Painter或多模型同屏。
    - 暂不做纹理、Z-buffer、透视投影、画质和功耗扩展。
