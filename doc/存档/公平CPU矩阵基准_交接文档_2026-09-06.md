# 公平 CPU-矩阵基准交接文档

更新时间：2026-09-06

## 目标与已确定的体系结构

论文比较三条路径，且三者应使用同一份 SK3D-v4 模型、相同的 Q8.8 变换规则、背面剔除、稳定 Painter 排序和 SketchBook 命令编码：

| 模式 | 工作分配 |
|---|---|
| `CPU_ONLY` | CPU 从 ExtRAM 读取模型，完成变换、剔除、排序和全部 SketchBook 命令。 |
| `CPU_MATMUL` | CPU 从 ExtRAM 读取模型；矩阵乘法外设仅做 4x4 Q8.8 矩阵乘法；CPU 取回结果后完成剔除、排序和全部 SketchBook 命令。 |
| `SCENE_CONTROLLER` | 保持原有全硬件 Scene Controller 路径，不作为 CPU_MATMUL 的缓存或数据通路。 |

`CPU_MATMUL` 的公平性约束不可回退：

- 不给矩阵外设增加 AXI master、ExtRAM 读取、模型缓存、变换顶点缓存或 SketchBook 直连。
- CPU 每帧加载一次变换矩阵；每次从 ExtRAM 读取最多四个顶点，作为矩阵 B 的四列写入外设，再轮询并读回四列结果。
- 计时必须包含 ExtRAM 读取、MMIO 写操作数、启动/轮询和读结果。

## 已落地的代码

### 固件和驱动

- `sdk/software/examples/rt_3d/rt_3d.c`
  - 已改为直接解析 `0x1c400000` 的 SK3D-v4：头、顶点记录和三角形记录均由 CPU 读取。
  - 已实现 `CPU_ONLY` 的 Q8.8 软件矩阵变换、剔除、稳定深度排序及 `CLEAR + TRIANGLE_FLAT* + PRESENT`。
  - 已实现 `CPU_MATMUL` 的四顶点列批处理。CPU 写入矩阵 A、四列矩阵 B，启动、轮询、读取 C；之后复用同一套几何和命令路径。
  - Scene Controller 路径仍在同一文件中。
  - `rt_3d.h` 的 SK3D magic 已从旧的 `RTD3` 修正为 `0x534B3344`（`SK3D`）。

- `sdk/software/bsp/include/matmul.h` 和 `sdk/software/bsp/drivers/matmul.c`
  - 已增加 `matmul_set_mode_fixed_q8_8()`、`matmul_read_fixed_c_word()` 及 fixed-mode 控制/状态位定义。

### 矩阵外设

- `rtl/ip/matmul/matmul_axi_slave.v`
  - 保留原有 A/B/C 寄存器映射和 legacy unsigned 行为。
  - 控制寄存器 bit 2 增加 signed fixed Q8.8 模式。
  - fixed 模式将 A/B 各元素低 16 位按有符号 Q8.8 相乘，累加后算术右移 8 位并写回 C。
  - 状态寄存器增加 fixed-mode 标志；代码中已放置 fixed overflow/error 路径，但其可达性和语义仍需以独立单元测试确认。

### 实验入口与 SoC 烟测

- `experiments/3d_scene/Makefile`
  - 支持 `MODE=CPU_ONLY|CPU_MATMUL|SCENE_CONTROLLER`、`MODEL=S0..S4`。
  - formal 默认配置仍为 30 warmup / 300 measured / 5 repetitions。
  - `smoke` 显式使用 1/1/1 的短配置，避免用 formal 配置做 RTL 冒烟。

- `experiments/3d_scene/scripts/run_scene_matrix.py`
  - 已接受三种模式，运行目录按 `run_id/mode/model` 组织。

- `sim/test/sketch_soc/rt_3d_soc_tb.sv`
  - CPU 模式检查 CPU 来源的 SketchBook `CLEAR/DRAW/PRESENT`。
  - `CPU_ONLY` 检查没有 Scene Controller 命令/模型读取。
  - `CPU_MATMUL` 额外检查矩阵 MMIO 的读写流量。
  - 首次 present 后等待第二个完成的 DVI capture，检查至少一个非黑像素，再导出稳定 PPM。
  - `FRAME_DUMP_LIMIT(0)` 保持不变，禁止修改。

## 下一位 Agent 的优先执行步骤

### 1. 修正并验证 smoke

先确认 `experiments/3d_scene/Makefile` 中 `RUN_DIR` 与 Python 运行器一致。当前 Makefile 是：

```make
RUN_DIR := $(ROOT)/experiments/3d_scene/runs/$(RUN_ID)/$(MODE)
```

应补上 `$(MODEL)`，避免 formal 的 S0--S4 写入同一目录：

```make
RUN_DIR := $(ROOT)/experiments/3d_scene/runs/$(RUN_ID)/$(MODE)/$(MODEL)
```

然后依次运行：

```powershell
make -C experiments/3d_scene MODE=CPU_ONLY MODEL=S0 smoke
make -C experiments/3d_scene MODE=CPU_MATMUL MODEL=S0 smoke
make -C experiments/3d_scene MODE=SCENE_CONTROLLER MODEL=S0 smoke
```

每次 Verilator 批处理后必须先读取 `fpga/verilator/results/rt_3d_soc_tb.json`。失败时不要直接读取完整 transcript，使用：

```powershell
python C:\Users\123\.codex\skills\verilator-batch-debug\scripts\transcript_summarize.py --log fpga/verilator/logs/transcript_rt_3d_soc_tb.log
```

验收条件：JSON 为 PASS；CPU 模式 UART 已输出 frame JSON；TB 的 non-black DVI 断言通过；`CPU_ONLY` 无 Scene 流量；`CPU_MATMUL` 有矩阵 MMIO 流量。

### 2. 补齐矩阵外设独立回归

目前没有新增的、可自动执行的矩阵外设单元 TB。必须新建或扩展现有 matmul TB，至少覆盖：

- legacy unsigned 结果与原实现一致；
- Q8.8 signed 正负坐标；
- 四顶点列批处理的 C 行/列布局；
- start/busy/done 轮询；
- overflow/error 状态。

建议先检查 `sim/matmul_flow_tb.v` 是否覆盖 legacy 行为，并增加专用 Verilator filelist/目标；不要只依赖 Icarus 的语法通过。

### 3. 补齐正式 JSONL 与 CRC 闭环

当前 `rt_3d.c` 的帧 JSON 仍不能视为完整实验数据：`frame_crc`/等价状态没有与 DVI monitor 的 framebuffer CRC 闭环。需要：

- 每帧同时记录命令 CRC 和 **monitor 导出的 framebuffer CRC**；
- 将同一模型、同一帧号的三模式 CRC 进行比较；
- 仅在三模式都通过 CRC 等价时，允许统计脚本绘图；
- 将 `PENDING`/不一致结果拒绝进入正式汇总。

注意：当前 testbench 会在早期帧验证并结束，不能直接充当 300 x 5 的最终采集器。需要明确 formal capture 策略，避免 1500 帧 PPM 输出，同时保持 `FRAME_DUMP_LIMIT(0)` 不变。

### 4. 运行正式实验

以上全部通过后才可执行：

```powershell
make -C experiments/3d_scene MODE=CPU_ONLY run-matrix
make -C experiments/3d_scene MODE=CPU_MATMUL run-matrix
make -C experiments/3d_scene MODE=SCENE_CONTROLLER run-matrix
```

随后执行 `validate`、CRC golden/equivalence 检查及 `summarize`。正式结果必须保留生成器版本、资产 SHA-256、模型维度、模式、warmup/frames/repetitions 和仿真工具版本。

## 风险与排查重点

- CPU 剔除方向、投影或 triangle winding 可能使 S0 可见三角形数为零；SoC smoke 的非黑断言会立即暴露。
- CPU mode 的 SketchBook 事务应通过 arbiter 可见；TB 不能只计 MMIO 总数，必须结合 Scene 事务为零的断言判断来源。
- fixed Q8.8 的输入/输出都是低 16 位有符号数；C 与 RTL 的截断、右移和溢出策略必须逐项对齐。
- 正式 CRC 不能只用命令 CRC 替代 framebuffer CRC；两者都必须保留，前者用于诊断命令差异，后者用于验证实际绘制。
- 工程有用户已有的未提交改动和自动生成的 `sdk/software/examples/rt_3d/obj/*`，交接时不可使用 `git reset --hard` 或覆盖性 checkout。
